# NYAYAI – Mandatory Development & Engineering Rules

All engineers (**Ayushi Sharma, Anu Sharma, Ridhi Mashi, Dhananjay Sharma**) must strictly adhere to the following 15 engineering rules. Violations will cause pull request rejections and break forensic admissibility in production.

---

### Rule 1: Never Delete Working Functionality
- Prior working code, tests, and interfaces must remain intact.
- When refactoring or upgrading an algorithm, maintain backwards-compatible wrappers or versioned interfaces (`v1`, `v2`).

### Rule 2: Never Overwrite Original Evidence Files
- Original evidence files uploaded into the vault are strictly **Write-Once-Read-Many (WORM)**.
- Any engine analyzing a file must read a stream or operate on a temporary working copy. Original files must be marked read-only on disk (`chmod 0444` / read-only attribute).
- Modifying, transcoding, compressing, or replacing an original file is a fatal compliance violation.

### Rule 3: Never Commit Credentials
- Passwords, secret keys, private keys, database connection strings with passwords, and API tokens must **never** be checked into git.
- All secrets belong in `.env`, which is ignored by `.gitignore`.

### Rule 4: Use Environment Variables
- All configuration values (ports, vault paths, DB URIs, model paths, token lifespans) must be loaded through the unified configuration module (`backend/app/core/config.py`) using environment variables.

### Rule 5: Every Evidence Must Have a Unique `evidence_id`
- Evidence items must be addressed globally by a standardized unique identifier (e.g. `EVD-YYYY-XXXX`).
- No anonymous or untracked digital artifacts may enter the system.

### Rule 6: Every Case Must Have a Unique `case_id`
- Every investigative container must carry a globally unique case identifier (e.g. `CASE-YYYY-XXXX`).
- Multi-tenancy and data isolation are enforced at the `case_id` boundary.

### Rule 7: Evidence Integrity Must Use SHA-256
- SHA-256 is the mandated cryptographic hash algorithm for all evidence verification, custody chaining, and report certification.
- Deprecated algorithms like MD5 or SHA-1 are strictly prohibited for evidentiary proof.
- Hashing must be performed via chunked streaming to handle large binary files without memory exhaustion.

### Rule 8: Every Important Evidence Action Must Be Auditable
- Every intake, retrieval, analysis execution, view, export, and status update must produce an immutable record in the Chain of Custody ledger.
- Each custody event must be cryptographically chained to the previous event hash.

### Rule 9: AI Results Must Remain Linked to `evidence_id`
- All inference outputs, bounding boxes, transcripts, and tamper scores must reference the primary `evidence_id` and the evidence file's `sha256_hash` at the time of inference.
- An AI result without an immutable link to its exact evidence version is inadmissible.

### Rule 10: API Contracts Must Be Documented
- Any addition or modification to REST API routes, schemas, headers, or query parameters must be documented in `docs/API_CONTRACTS.md` before merging.
- OpenAPI specs generated by FastAPI must remain consistent with documentation.

### Rule 11: Database Changes Must Be Documented
- Direct alterations to tables or columns without an updated specification in `docs/DATABASE_SCHEMA.md` and an associated migration are prohibited.
- Foreign keys and unique constraints must never be bypassed.

### Rule 12: Do Not Silently Change Response Formats
- Modifying the keys, types, or structure of an existing API response breaks other engineers' work.
- Deprecations require advance team agreement, version increments, or backwards-compatible extensions.

### Rule 13: Do Not Invent AI Accuracy
- Do not produce fake 99.9% certainty or hardcoded false precision metrics.
- AI models must output realistic, empirically calibrated confidence probabilities (0.0 to 1.0) accompanied by explainability metrics and confidence bounds.

### Rule 14: Do Not Claim Forensic Certainty Without Evidence
- Distinguish between **mathematical certainty** (cryptographic hash matches/mismatches) and **probabilistic inference** (statistical anomaly scores from deep learning models).
- AI detections must be flagged as "Screening Indicators" or "Anomalies", never as "Absolute Proof" unless verified by deterministic file-structure forensics.

### Rule 15: Keep Modules Independently Testable
- Every module (`forensic-engine`, `ai-engine`, `correlation`, `custody`, `explainability`, `reports`, `backend`) must possess its own independent interface contracts, dependencies, and unit tests.
- No engine may require a live HTTP connection to another engine to run its internal test suite.
